# EanHost Android v1.0.0-beta.1

First beta of the EanHost Android control plane: a browser dashboard for a fleet
of Android tablets running Termux, with durable device jobs, a supervised bot
runner, and optional Fast Mode.

**This is a beta.** It has been exercised on a four-tablet fleet (A10e, T337T,
T380, T380-2), but treat it as pre-release software and keep it on a trusted
LAN.

## Highlights

- **Per-node Fast Mode** — a Fast on/off button on each dashboard card and in
  Settings. Enable it one tablet at a time; every operation still falls back to
  ADB when the TCP path is unavailable. In the reference fleet, status latency
  dropped from roughly 30–46 ms (adb) to 6–16 ms (tcp).
- **Correct file browsing on minimal `ls` builds** — devices that omit the
  link-count or directory-size columns now render normal folder/file rows
  instead of raw `ls -l` output.
- **Logout actually logs you out** — the session token is revoked and the cookie
  is expired.
- **Incremental log tail** — only newly appended bytes are fetched, with a
  separate `runner` log source.

## Install

```bash
git clone https://github.com/Eandab0t/EanHost-Android.git
cd EanHost-Android
python3 panel/panel.py --set-pass '<your-password>'
adb devices
./provision-node.sh <adb-serial> <friendly-name>
bash eanhost-up.sh
```

Open `http://<host-ip>:8443`.

Requirements: Linux host with Python 3 and Android platform-tools; each tablet
with USB debugging and Termux (`pkg install python bash`).

## Upgrade from an earlier checkout

1. Back up `panel/config.json` (it is now git-ignored and no longer tracked).
2. Update the code.
3. Restart the panel: `bash panel/start.sh`.

Existing `config.json` files keep working; `fast_mode`/`fast_nodes` are read with
sane defaults when absent.

## Known limitations

- HTTP only, no built-in TLS. Use a trusted network or a reverse proxy.
- Panel sessions are in-memory; a restart signs everyone out.
- Fast Mode requires a matching `runner.json` on each device and an
  `adb forward` tunnel.
